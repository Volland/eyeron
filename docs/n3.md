# <img src="https://josd.github.io/images/eye.png" alt="" width="32" height="32"> Language and runtime reference

Eyeron evaluates Notation3 rules over N3 and RDF input. See [the guide](guide.md) for commands, formats, APIs, and proof workflows.

## Terms and rules

```n3
@prefix : <http://example.org/>.
:Socrates a :Human.
{ ?x a :Human } => { ?x a :Mortal }.
```

The parser supports prefixes, bases, IRIs, variables, blank nodes, literals, lists, and quoted graph terms. `=>` names `log:implies`; `<=` names `log:impliedBy` and registers a backward rule. Rules may generate rules or unquote a graph supplied as their conclusion. `=`, the syntax for `owl:sameAs`, asserts a relation; substitutions through opaque quoted graphs require explicit rules, as in [graph-term-opacity.n3](../examples/graph-term-opacity.n3).

Lists remain `Term::List` values. They can also be inspected through virtual `rdf:first`/`rdf:rest` matching and list built-ins. Quoted graphs and rule sides are `Graph` values with `universals`, `existentials`, and `triples`. `Term::formula` and `Rule::new` accept triple vectors too.

### Explicit quantification and graph terms

```n3
@prefix : <http://example.org/>.
@forAll :x.
@forSome :y.
:x :loves :y.
```

This means “everybody loves somebody.” Declarations precede the graph's first triple, with `@forAll` before `@forSome`. Each IRI may be declared once per graph; comma-separated IRI lists are accepted. Prefix/base resolution happens before binding lookup. Quantified IRIs work in every triple position and remain accessible in nested graphs; an inner declaration can shadow an outer one.

Implicit `?x` variables belong to the outermost graph. Blank nodes belong to their innermost graph. `?x` and `_:x` are distinct variables. To put an existential outside a universal, nest the universal:

```n3
@prefix : <http://example.org/>.
@forSome :beloved.
{} => { @forAll :person. :person :loves :beloved }.
```

Graph terms retain their binders and are compared as sets, up to bijective renaming of locally bound variables of the same quantifier kind. Duplicate triples and unused declarations do not change identity. Substitution reaches free variables inside nested graphs while preserving local binders. A graph with locally quantified variables can therefore be ground; a graph referring to an outer universal remains open.

Universal assertions are instantiated on demand rather than enumerating an infinite closure. Existential witnesses depend on the universal assignment within their scope. `log:includes` tests existential consequence without instantiating the subject graph's universally quantified variables.

Examples: [graph terms and unquoting](../examples/graph-terms.n3), [explicit quantification and shadowing](../examples/explicit-quantification.n3), [existential rule](../examples/explicit-existential-rule.n3), [universal instances](../examples/universal-instances.n3), [graph inclusion](../examples/graph-includes.n3), and [shared existential](../examples/shared-existential.n3).

### Inference fuses

A rule with conclusion `false` forbids its premise. If the premise succeeds, reasoning stops and sets `ReasonerResult.fuse`. The CLI prints the fired rule and its matched instance and exits with status 65. This does not implement general classical reasoning from a contradiction.

## Evaluation and output

Explicit facts seed the materialized closure. Forward rules add unseen conclusions until saturation, a fuse, or a reported limit/error. Fact indexes and an agenda accelerate eligible rules; other rules use general premise matching. Backward rules are standardized apart and searched on demand with cycle/depth controls. Universal assertions also supply answers on demand, so the materialized closure does not enumerate every universal instance.

Scoped collection and negative tests are deferred until ordinary forward reasoning is saturated, then reconsidered if more facts are derived. `log:query` runs after that stage, selecting answers without feeding them back into the closure.

`ReasonerResult` separates input facts, derived results, and materialized closure. Normal output serializes derived results, or query answers when queries are present. `log:outputString` results override triple serialization with concatenated text. `--proof` instead writes a proof of the derived claims; see [the guide](guide.md#proofs-and-their-limits).

### Resource limits

`ReasonerOptions` supplies these default budgets. The CLI exposes `--max-backward-depth`; the other fields are library settings.

| Field | Default | Scope |
| --- | --- | --- |
| `max_iterations` | 1,000,000 | Forward outer passes plus agenda steps |
| `max_match_steps` | 200,000 | Steps in one premise search |
| `max_backward_depth` | 32 | Recursive backward search depth |
| `max_backward_solutions_per_goal` | 1,024 | Retained substitutions for one backward goal |
| `max_term_bytes` | 16 MiB | Term text in one derived fact |

Reaching a reasoning budget is reported through `limits_reached`, completion status, and `incomplete_summary()`. These are operation/term budgets, not a whole-process memory or wall-clock limit. A single firing can produce multiple facts, so `max_iterations` is not a closure-size cap.

Term nesting is capped at 64 levels: deeper input is a parse error; deeper derived terms report `ReasonerLimit::TermDepth`. `string:format` refuses field widths larger than the default term-byte bound and yields no binding. Exact integer exponentiation also has a fixed size guard. Invalid built-in arguments usually produce no match rather than an incomplete run.

## Built-ins

These names are dispatched in [reasoner.rs](../src/reasoner.rs). Supported argument directions depend on the built-in; an unbound input is not generally an invitation to enumerate values.

| Namespace | Names |
| --- | --- |
| `log:` | `equalTo`, `notEqualTo`, `collectAllIn`, `forAllIn`, `conclusion`, `conjunction`, `includes`, `notIncludes`, `uri`, `rawType`, `dtlit`, `langlit`, `content`, `semantics`, `semanticsOrError`, `parsedAsN3`, `skolem`, `uuid` |
| `math:` | `sum`, `difference`, `product`, `quotient`, `integerQuotient`, `remainder`, `exponentiation`, `negation`, `absoluteValue`, `rounded`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `sinh`, `cosh`, `tanh`, `degrees`, `greaterThan`, `lessThan`, `notGreaterThan`, `notLessThan`, `equalTo`, `notEqualTo` |
| `list:` | `first`, `rest`, `firstRest`, `last`, `length`, `member`, `memberAt`, `in`, `notMember`, `remove`, `append`, `reverse`, `sort`, `iterate`, `map` |
| `string:` | `lessThan`, `greaterThan`, `notLessThan`, `notGreaterThan`, `concatenation`, `contains`, `containsIgnoringCase`, `startsWith`, `endsWith`, `equalIgnoringCase`, `notEqualIgnoringCase`, `format`, `matches`, `notMatches`, `replace`, `scrape` |
| `time:` | `year`, `month`, `day`, `hour`, `minute`, `second`, `timeZone`, `localTime` |
| `crypto:` | `sha` |

Namespace prefixes above use `http://www.w3.org/2000/10/swap/` plus the namespace name and `#`. Additional datatype inspection predicates are `datatype` and `lexicalForm` under `https://eyereasoner.github.io/eyeron/datatype#`, with the corresponding `eyeling` namespace aliases. The nonstandard `https://eyereasoner.github.io/eyeling/vocab/sudoku#solve` solves an 81-character Sudoku string.

### Behavior to account for

- Graph terms are opaque and preserve literal lexical identity. Ordinary numeric matching/comparison can recognize numerically equal values written differently.
- The six math comparison predicates also compare `xsd:date` and `xsd:dateTime` by parsed instants; dates use midnight and absent time zones use UTC. Durations retain their own comparison conversion.
- Regular expressions use Rust's Unicode-aware engine, with compatibility handling for specific look-around forms covered by the tests.
- `log:collectAllIn` returns one list for its scoped clause. A blank node already supplied by an outer binding is a fixed value; a syntactic blank in the clause is an existential pattern.
- `log:uuid` returns a deterministic UUID-shaped string based on SHA-1 of a term's text, with version/variant bits. It does not include a UUID namespace. Different literal datatypes can share a result when their lexical text is the same. `log:skolem` instead returns an IRI.
- `log:content` and `log:semantics` recognize the bundled `HELLO` fixtures. They do not fetch arbitrary resources. `log:semanticsOrError` returns a resource-error string for other IRIs. CLI URL input is fetched by the CLI separately.

## RDF Messages

Normal replay parses a whole RDF Message Log into `eymsg:` envelopes and quoted message payloads, which rules can inspect with `log:includes`. See [rdf-messages.n3](../examples/rdf-messages.n3) and its [input](../examples/input/rdf-messages.trig).

For independent message processing:

```bash
eyeron --rdf --stream-messages \
  examples/alma-rdf-messages.n3 \
  tests/input/alma-rdf-messages-small.nt
```

The streaming path incrementally reads local files or HTTP(S), reasons over each payload with a prepared N3 program, and flushes its RDF output. It retains no derived facts between payloads. It requires `--rdf` and rejects stdin message logs, `--proof`, `--prove-and-check`, `--check-proof`, `--ast`, and `--stream`.

## Compatibility and current limitations

The RDF parser profiles are exercised against the vendored RDF 1.1/1.2 manifests. That test coverage does not imply implementation of every historical N3 extension or a complete OWL reasoner. Eyeron has no persistent graph store, query service, or custom external built-in loader. Compatibility-only CLI flags are listed in [the guide](guide.md#cli-options).

N-Triples and N-Quads accept an uppercase `VERSION "1.2"` announcement on its own line, using a double-quoted short string and no trailing period. Prefix, base, and Turtle-style `@version` directives remain invalid in these line syntaxes.

### Conformance scope differences

The N3 conformance harness explicitly expects no wildcard conclusion for two vendored cases: `static/success-literal-22.n3` treats a quoted blank as a wildcard, and `generated/log/forAllIn/success-objectNotInstantiated-2.n3` treats a blank supplied by an outer binding as a wildcard. The vendored files are unchanged; the harness checks Eyeron's scoping behavior instead of those two upstream success expectations.
